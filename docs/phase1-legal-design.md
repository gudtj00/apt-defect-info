## 금지어 lint — 문맥 구분 설계 (중요한 판단)

브리핑 원안은 "부실·불량·위험·최악·엉터리·조심·피하세요·주의하세요·블랙리스트"를 **사이트 전체**에서 금지하는 것이었다. 그런데 하자판정기준 고시(국토교통부 고시 제2026-360호) 원문을 직접 확인한 결과, "불량"은 법정 용어로 계속 등장한다:
- 제24조: "작동·기능불량", 제27조: "기능불량", 제28조: "작동·기능불량", 제40조: "작동불량", 제105조: "조명설비류 보수비용" 등 조문 전반에서 "규격오류·작동기능불량·부착접지결선불량"이 표준 서술 방식이다.

이걸 사이트 전체에서 문자 그대로 금지하면 **Phase 3 하자 유형 사전이 법령을 인용할 때마다 lint에 걸려 빌드가 막힌다.** 원안 그대로 구현하는 건 브리핑의 진짜 의도(건설사에 대한 사적 낙인찍기 방지)를 지키는 게 아니라 오히려 서비스의 핵심 콘텐츠(축②)를 마비시키는 결과를 낳는다.

그래서 두 그룹으로 나눴다:

- **`BANNED_WORDS_ALWAYS`** (최악·엉터리·피하세요·주의하세요·블랙리스트): 법령 원문 어디에도 등장하지 않는 순수 평가어. 사이트 어디서든 무조건 차단.
- **`BANNED_WORDS_BUILDER_SCOPED`** (부실·불량·위험·조심): 법령 원문에 정식 용어로 등장하므로, **건설사를 지목·평가하는 콘텐츠(`/builder`, `/rank`, `content/builders/`)에서만** 차단한다. 하자 유형 사전처럼 법령을 인용하는 콘텐츠에서는 검사하지 않는다.

구현: [lib/legal-constants.ts](../lib/legal-constants.ts) (상수 정의) + [scripts/legal-lint.mjs](../scripts/legal-lint.mjs) (스캐너, CI 게이트) + [scripts/legal-lint.test.mjs](../scripts/legal-lint.test.mjs) (회귀 테스트 — 법령 인용은 통과, 건설사 폄훼는 차단하는지 케이스별로 검증함).

CI 워크플로는 [.github/workflows/legal-lint.yml](../.github/workflows/legal-lint.yml)에 있다. **이 저장소는 아직 git/GitHub에 연결되지 않았으므로 워크플로는 지금 당장은 동작하지 않는다** — git init 및 원격 저장소 연결 후 push하면 활성화된다.

## 판정 건수 vs 판정 비율 — 절대 섞지 않는다

- 판정 비율의 정의: **하자 건수 ÷ 판정받은 단지의 공급세대수**. 소규모 단지일수록 구조적으로 불리해지는 지표다(빌텍종합건설 244.4%, 5년 누계 2,600% 초과 사례가 실제로 있음 — Phase 0 실사에서 확인).
- Phase 2 스키마(`builder_defects` 테이블)에서 건수와 비율을 **별도 컬럼**으로 저장하고, Phase 4 UI에서도 별도 라벨·별도 색상으로 표시한다. 비율을 표시할 때는 반드시 [`RATIO_CAVEAT`](../lib/legal-constants.ts) 문구("이 비율은 판정받은 단지의 공급세대수 대비 하자 건수이며, 소규모 단지일수록 높게 나오는 지표입니다.")를 함께 노출한다.

## 표준 문구 (Phase 2/4에서 재사용)

`lib/legal-constants.ts`에 정의:
- `STANDARD_DISCLAIMER`: 모든 페이지 하단 — "본 정보는 {날짜} 시점 공표 자료이며 이후 변경됐을 수 있습니다."
- `CALC_DISCLAIMER`: 담보책임기간 계산 결과 화면 — "법정 기간 계산 결과이며, 실제 청구 가능 여부는 인도일·하자 발생 시점 등에 따라 달라질 수 있습니다."
- `CORRECTION_SLA_BUSINESS_DAYS = 3`: 이의신청 처리 기한.
- `RATIO_CAVEAT`: 판정 비율 표시 시 항상 동반.

## 축③ 로컬 프로토타입 — 만들었다가 되돌림 (2026-08-06)

사용자가 "로컬에서만 작업하니 지금은 리스크가 없다, 변호사 검토는 나중에 받고 구현된 걸 먼저 보고 싶다"고 요청해서, 이 문서가 정한 안전장치를 전부 적용한 로컬 프로토타입(`/builder`, `/about`, `data/builder-defects.json`)을 실제로 만들었다.

- **실제 데이터**: 국토교통부 정책브리핑(korea.kr)에서 6차 공개(2026-03-29 공표) 보도자료 원문 PDF를 직접 다운로드해서 4개 표(건수 기준 6개월/5년, 비율 기준 6개월/5년, 각 20개사)를 그대로 전사했다.
- **적용했던 안전장치**: `lib/legal-constants.ts`의 `RATIO_CAVEAT`·`STANDARD_DISCLAIMER`·`CORRECTION_SLA_BUSINESS_DAYS`를 실제로 사용, `/about` 페이지로 수록 기준을 명문화, 이의신청 mailto 링크와 SLA 고지, 법인명·판정건수·비율·공표회차·출처링크만 게재(대표자명·연락처·주소 미게재), `scripts/legal-lint.mjs`의 `/builder` 경로 스코프 검사 통과 확인함.

**그런데 완성본을 보고 나서 사용자가 스스로 재검토했다.** "이 기능이 서비스에서 어떤 의미가 있냐"는 질문에, 축①·②는 "이미 입주한 사람이 자기 집을 확인"하는 용도인데 축③은 "아직 안 산 사람이 건설사를 고르는" 용도라 같은 사용 흐름이 아니라는 점, 그리고 보도자료 원문에 "'26년 하반기(7차 공개)부터는 하자심사·분쟁조정위원회 누리집(adc.go.kr)에 직접 게시할 예정"이라고 명시돼 있어 이 기능의 차별점이 곧 사라진다는 점을 근거로 들어 우선순위를 낮추자고 답했고, 사용자가 동의하며 **전체 롤백을 요청**했다.

- `app/builder/`, `app/about/`, `data/builder-defects.json`, `raw/axis3/press_release.pdf`, 네비게이션 링크를 전부 삭제했다.
- `content/legal/about-draft.md`(Phase 1 원안 문서)와 `lib/legal-constants.ts`(공용 상수)는 남겨뒀다 — 나중에 축③을 다시 시작하게 되면 그대로 재사용하면 된다.
- **결론**: 축③은 "만들 수는 있지만 지금 우선순위에 넣을 이유가 약하다"는 게 실제로 프로토타입까지 만들어보고 나서 내린 결론이다. 다시 논의할 일이 있으면 이 절과 [[project_apt_defect_info_future_roadmap]]을 먼저 참고할 것.
